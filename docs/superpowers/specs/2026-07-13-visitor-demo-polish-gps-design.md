# 游客端演示体验与定位容错设计

日期：2026-07-13  
状态：已确认视觉方向，待实施  
视觉选择：A「舞台留白」

## 1. 目标与实施顺序

本轮先提高演示界面的审美、文案与数字人呈现，再实现 GPS 与难定位场景。不得新增独立页面，不开展转弯级导航，不牺牲已经接通的 FAQ 快速通道、Qwen 首句流式、分段 TTS、OpenTalking WebRTC 和浏览器端延迟采集。

成功标准：

1. 数字人不再贴住页面底边或遮挡主要字幕，脸部仍足够大，可观察口型和细微表情。
2. 字幕、状态、正文、评分和追问形成清楚层级，演示时不出现技术字段或过长提示。
3. OpenTalking 视频保持原始帧和音视频链路，视觉缩放只发生在展示层，不降低生成分辨率或破坏口型采集 ROI。
4. 定位功能按需开启；GPS 正常、弱信号、权限拒绝、超时和浏览器不支持时都能继续导览。
5. 没有经过核验的景点坐标时，不展示虚假的米级距离，不把 AI 鸟瞰图描述为真实比例地图。

## 2. 演示界面设计

### 2.1 数字人舞台

采用已确认的「舞台留白」构图：

- 桌面端数字人媒体框从当前接近半屏的尺寸缩至左侧舞台约 40% 至 44% 宽，整体上移并在底部预留字幕空间。
- 保留脸部和上半身，避免只剩头像，也避免身体贴到浏览器底边。
- OpenTalking 的 720 × 720 视频仍使用完整媒体坐标系；仅调整外层容器尺寸、位置和裁切策略。
- 状态胶囊移到数字人上方，与人物中心对齐，使用游客可理解的状态：`导游在线`、`正在聆听`、`正在整理`、`正在讲解`、`讲解已暂停`。
- 不向游客显示 QuickTalk、WebRTC、provider、session、模型 ID 或服务状态英文。

### 2.2 字幕与文字位置

- 字幕从覆盖服装的深色大条改为独立浅色讲解条，放在数字人媒体框下方，不盖住胸口、口型或风景主体。
- 字幕最多显示两行，每行保持舒适长度；长回答继续在右侧对话区阅读。
- 字幕标题只保留一个当前状态和可选的当前讲解景点，不重复出现两套“正在讲解”。
- 手机端不再直接隐藏字幕，改为舞台下方的单行或两行紧凑字幕条。
- 字幕更新使用 `aria-live="polite"`，避免流式文字每个字符都触发重复朗读。

### 2.3 右侧对话层级

- 保留“对话 / 当前游线”双模式，不新增导航层级。
- 回答正文限制阅读宽度和段落间距；事实要点使用短段落，资料依据保持弱化但可见。
- “本次回答有帮助吗”、文字建议和追问建议不得与正文同时抢占视觉焦点：反馈区置于回答尾部，追问使用一行可换行标签。
- 输入框固定在面板底部；滚动内容不得被数字人或浮动按钮覆盖。
- 空状态、加载状态和失败状态只使用游客语言，例如“正在查找景区资料”“这次没有听清，可以再说一遍”。

### 2.4 后台与全站文案

- 保留真实能力、资料依据、非官方自测边界和现场公告提醒，删除重复解释与内部实现词。
- “本次自测如何计算”区域从三块松散大卡改成一个紧凑方法说明区：题集、判定、结果用途三个步骤保持等高、对齐和合适行长。
- 所有标题、说明、按钮遵循“动作 + 对象”或明确结果，例如“生成推荐游线”“选择附近地标”“重新定位”。
- 不把本地 17 题和隐藏 30 题成绩写成官方成绩，不把静态图写成真实地图。

## 3. 数字人质量、速度与表情

### 3.1 质量和速度保护

- 保留 FAQ 快速通道和 Qwen 首句流式输出；第一段 TTS 与后续文本生成并行。
- 继续复用已预热的 OpenTalking session，禁止因界面切换重建数字人或重新加载模型。
- 首段字幕与首段语音使用同一段文本，避免看到与听到的内容错位。
- 视觉调整后必须重新验证真实音频轨、视频轨、连续帧变化、可见嘴部运动和浏览器首响应采集。
- 不用缩短回答、预录音频或 mock 结果冒充速度提升。

### 3.2 表情状态

现有代码已经区分 `friendly / listening / thinking / speaking`，但目前这些 class 没有实际视觉效果。实施时增加克制的状态反馈：

- `friendly`：稳定正视、状态灯为绿色，舞台不做循环晃动。
- `listening`：状态胶囊和轻微呼吸光提示正在听，不遮挡脸部。
- `thinking`：低频柔和明暗变化，避免旋转加载图标或夸张动画。
- `speaking`：以真实 OpenTalking 口型视频为主，舞台只显示轻量语音状态，不叠加假嘴型。

如果当前 QuickTalk 素材没有独立情绪控制，只能称为“交互状态反馈和自然口型”，不能宣称已经实现真实面部情绪驱动。后续若增加经过一致性验证的表情素材，必须保证同一人物身份、服装和光照稳定，并单独做自然度人工检查。

## 4. GPS 与难定位场景

### 4.1 功能定位

功能名称统一为“定位辅助”，归属现有“当前游线”面板。它帮助确认当前站点和从哪里继续，不宣称实时导航、室内精准定位、自动绕行、转弯提示、预计到达时间或最短路径。

### 4.2 定位状态

前端维护以下会话状态：

```text
source: gps | manual | camera | none
status: idle | requesting | confirmed | uncertain | denied | unavailable | stale
accuracy_m: number | null
current_spot_id: string | null
observed_at: timestamp | null
```

状态处理：

- 用户主动点击“开启定位”后才请求浏览器权限，页面首次打开不得自动弹窗。
- 精度不高于 50 米且命中经过核验的景点坐标时，可建议当前景点，但仍允许游客确认。
- 精度 50 至 150 米时显示“大致位置”，不自动改变游线。
- 精度超过 150 米、8 秒无结果、位置过期或出现异常跳点时进入不确定状态。
- 权限拒绝、浏览器不支持、室内遮挡或离线时直接提供手动地标和相机识景，不阻断问答、语音或游线。
- 手动选择优先级最高；GPS 恢复后必须提示游客确认，不能静默覆盖。

### 4.3 游线内交互

信息顺序固定为：

```text
游线标题
定位辅助条
现有示意图
异常提示（仅需要时）
下一站卡片
全部站点
更换游线
```

主要文案：

- 未开启：`开启定位，查看附近景点`
- 正在获取：`正在确认你的位置…`
- 信号较弱：`当前位置不够准确，请选择一个你看得到的地标。`
- 权限拒绝：`未开启位置权限，也可以继续导览。`
- 室内或遮挡：`室内定位可能漂移，请选择你所在的景点。`
- 手动确认：`已按“灵山梵宫”作为当前位置继续导览。`

当前卡片的“当前选中”必须拆分语义：

- 浏览其他站点：`正在查看 · 第 N 站`
- 游线下一站：`下一站 · 第 N 站`
- 游客主动确认到达：`已到达 · 景点名`

### 4.4 坐标与示意图边界

- 当前 `map_x / map_y` 继续只负责示意图排版，绝不参与经纬度计算。
- 新增独立、可审计的景点坐标注册表，字段包含 `spot_id`、`latitude`、`longitude`、`coordinate_system`、`arrival_radius_m` 和 `source`。
- 资料包未提供坐标，默认注册表不得用 AI 猜测填充。没有核验点位时，真实 GPS 只能判断信号质量，站点确认回退到手动选择或相机识景。
- 可提供显式标记的 `location-demo` 演示模式，用于复现弱信号、拒绝和超时；演示数据必须显示“模拟场景”，不能混入真实验收报告。

### 4.5 隐私

- 原始经纬度只保存在当前浏览器内存，不写入 localStorage、问答日志或管理后台。
- 后端最多接收游客主动确认的 `spot_id`，不把原始坐标发送给 Qwen。
- 定位辅助提供“停止定位”，离开页面时清理 `watchPosition`。

## 5. 组件边界

- `DigitalHuman`：只负责媒体、状态与字幕舞台，不处理问答或定位。
- `TouristExperience`：协调问答、语音、数字人、游线和定位状态，但定位细节下沉到独立 hook。
- `useVisitorLocation`：封装权限、超时、精度、陈旧位置和停止监听。
- `locationMath`：纯函数完成精度分类、Haversine 距离、最近点和坐标注册表校验，便于单测。
- `ItineraryPanel`：显示定位辅助条、手动地标选择和当前/下一站语义，不直接调用浏览器 API。
- 后端路线接口只接受可选 `start_spot_id`；没有道路拓扑时只从已确认站点继续展示现有游线，不声称重新计算最短路。

## 6. 错误处理与降级

- 定位失败不得触发全局错误提示或清空现有游线。
- 没有坐标注册表、坐标系不匹配、数据源缺失时自动关闭最近点匹配，并提示选择地标。
- OpenTalking 暂时不可用时保留字幕和真实 TTS；不得用 CSS 嘴型或静态海报冒充实时口型。
- GPS 与数字人互不依赖，任何一方失败都不能破坏另一方。

## 7. 验证要求

### 自动验证

- 现有 141 个后端测试、15 个验收脚本测试、全部 audit、类型检查和生产构建继续通过。
- 新增数字人布局与游客文案审计，防止字幕重新覆盖人物或技术文案回流。
- 新增定位纯函数测试：精度阈值、超时、陈旧位置、异常跳点、最近点阈值、坐标系缺失和停止监听。
- 新增组件测试或静态审计：首次加载不请求权限，拒绝后可手动选择，未配置坐标时不显示虚假距离。

### 现场验证

- 真实桌面与手机各检查一次数字人裁切、字幕、输入框和当前游线。
- 重跑 OpenTalking WebRTC 六项检查及浏览器首音节/首个可见口型采集。
- GPS 至少验证一次真实手机定位、一次权限拒绝、一次弱信号或超时模拟、一次手动地标继续导览。
- 最终录制真人演示视频，人工检查口型、语音、表情状态和界面遮挡。

## 8. 非目标与答辩口径

本轮不做：

- 新游客页面或全屏地图页。
- 高德、百度或 Mapbox 转弯级导航。
- 未经来源核验的景点经纬度。
- 室内蓝牙、UWB 或视觉 SLAM 定位。
- 通过隐藏技术状态、mock 或预录结果制造通过证据。

可以表述：

> 系统采用按需定位与置信度分级。室外 GPS 可用时辅助确认当前位置；弱信号、室内遮挡或权限拒绝时，游客可以选择眼前地标或拍照识景，问答与游线不中断。

不能表述：

- 已实现景区精准 GPS 导航或精准室内定位。
- 当前 AI 鸟瞰图是真实比例地图。
- 浏览器模拟数据属于真实现场 GPS 证据。
