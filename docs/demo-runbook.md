# 7 分钟演示脚本

演示主线只讲三件事：回答有资料依据、数字人真实会动、后台能落地运营。游客端只说中文业务语言，不展示模型名、服务地址、配置键或预热状态。

## 演示前检查

```powershell
# 离线回归，不作为赛事证据
npm run self-check
npm run live-check

# 先在游客页 /?benchmark=1 完成 30 次真人语音提问；控制台导出：
# window.__LINGJING_E2E_BENCHMARK__.download()
# 将文件保存到 reports/quality/browser-e2e-samples.json 后做 strict live 验收
$env:COMPETITION_E2E_SAMPLE_FILE="reports/quality/browser-e2e-samples.json"
npm run competition-check
```

`npm run self-check` 固定使用 mock ASR/TTS，只证明代码、测试、构建和离线页面回归；不能把它的 `ok=true` 当成赛事链路就绪。浏览器采集器以录音停止为起点，必须同时检测到真实音频播放和 WebRTC 嘴部 ROI 变化，权威总时延取两者中较晚者；阶段诊断值不相加。没有 30 次浏览器真实样本时，可运行 `npm run competition-check:static` 做静态回归，但同样不构成赛事证据。

同时确认：

- 管理端“景区知识”显示 3 份基础资料。
- `reports/quality/frozen-qa-latest.md` 显示 17/17、100%，并标注“非比赛官方评测”。
- `reports/quality/hidden-qa-latest.md` 显示 28/30、93.33%、请求成功率 100%，同样标注为本地非官方评测；不要把后续两题定向复测表述成完整 30/30。
- `reports/quality/opentalking-webrtc-latest.json` 的六项检查均为 true。
- 游客端只有一个数字人，WebRTC 画面出现后静态海报会隐藏。
- 语速、音量各切换一次，耳朵能听出明显变化。

## 界面与状态检查

- 桌面端：数字人媒体框约占左侧舞台 40% 至 44%，保留脸部和上半身；字幕位于数字人媒体框下方，不遮挡口型、胸口或右侧对话。
- 手机端字幕仍然可见，最多两行；对话输入框位于面板底部且可直接操作。
- 状态顺序：导游在线 → 正在聆听 → 正在整理 → 正在讲解；暂停后显示“讲解已暂停”。
- 状态反馈不代替真实口型；说话时必须由真实音频驱动的 WebRTC 视频证明嘴部运动。
- 系统开启“减少动态效果”后，状态文字和颜色仍然可见，聆听与整理的无限动画停止。
- 后台方法说明只展示题集、判定和结果用途，并明确本地自测不等于官方成绩。

## 7 分钟时间线

### 0:00–0:35 开场

打开游客端：“灵境导游是一位 7×24 小时在线的景区数字人导游，游客可以说话、打字或上传图片，获得有资料依据的讲解和游线建议。”

画面只保留数字人、对话和输入入口，不介绍 OpenTalking、WebRTC、QuickTalk 等实现名词。

### 0:35–1:35 可信资料问答

提问：“九龙灌浴平日演出时间是什么？”

展示完整时间、回答下方的资料依据，以及自然中文播报。说明核心景区事实来自 3 份本地资料，找不到可靠依据时不会编造。

### 1:35–2:20 真实语音与数字人

让回答继续播报，指出人物画面持续变化、嘴部随语音运动。切换语速和音量，确认当前声音立即改变；再演示暂停、继续和停止。

答辩口径：

> 当前回答由 Edge 中文神经网络语音生成，并上传到 OpenTalking 实时驱动。联调报告中 128 个说话采样帧全部唯一，音频上传到可见嘴部运动为 2364.5 毫秒。

不要把这句话扩展成“所有问答都在 5 秒内完成”或“自然度已经通过专家评测”。

### 2:20–3:25 个性化推荐游线

提问：“我喜欢历史文化，帮我规划半日游线。”

回答内先显示紧凑摘要，再切换右侧“当前游线”。展示地图上的 5 个站点和连线，点击“讲这一站”后路线仍然保留；只有主动关闭或生成新路线才替换。

### 3:25–4:05 多模态识别

上传一张景点图片或使用摄像头截帧，提问“我现在看到的是哪里？”说明图片理解与本地景区资料共同参与回答；不展示 API 名称和内部字段。

### 4:05–5:05 管理端：一张图更换数字人

进入“数字人形象”：

1. 上传一张授权正面形象图。
2. 修改显示名称或人设。
3. 选择中文声音并试听。
4. 点击“保存并应用”。

强调管理员只完成这四步，模型准备和预热由系统自动处理。页面不应出现配置键、模型 ID、服务地址、`unavailable` 等技术文案。

### 5:05–5:55 管理端：资料与反馈闭环

在“景区知识”展示 3 份本地基础资料；演示运营文档的新增、编辑、删除和更新检索。

在“游客感受”展示星级、文字反馈、情感趋势、关注主题、服务建议、管理备注和“待处理 → 已解决”闭环。

### 5:55–6:35 数据概览

展示服务人次、热门问答、满意度和服务趋势。说明运营样本与当日真实交互分开标注，避免把资料包 Excel 样本冒充实时客流。

### 6:35–7:00 质量与收束

打开“问答自测”，用业务语言解释：

> 系统使用固定 17 道景区问题，每题同时检查关键事实和资料依据；当前完整自测为 17/17、100%。独立隐藏 30 题完整自测为 28/30、93.33%，请求成功率 100%。这些都是研发自测，不替代比赛官方测试集。

收束到三个价值：缓解导游资源紧张、提供个性化深度体验、帮助景区用真实反馈持续改进服务。

## 现场应急

- **语音暂时不可用**：切到文本输入，保留资料增强问答主链路；不要播放 mock 音频冒充真实语音。
- **数字人暂时不可用**：保留字幕和语音，明确说明当前流式驱动未就绪；不要把静态海报或 CSS 动画称为实时口型。
- **回答超时**：使用已验证的固定问题继续演示，并如实说明完整问答延迟受外部大模型网络影响。
- **路线没有出现**：使用明确句式“我喜欢历史文化，帮我规划半日游线”。
- **旧页面出现两个人像或技术英文**：关闭旧端口进程，重新打开 `runtime-ports.json` 指向的当前前端并强制刷新。
